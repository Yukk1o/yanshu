# Yanshu v0.11 审计收口矩阵

状态：当前 v0.11 回归证据与未解决边界。

这份矩阵把已经报告过的信任边界问题绑定到当前实现与可重复证据。它不是“无缺陷证明”，也不把第三方依赖、操作系统或人工审查移入 Yanshu 的可信计算基。

## 已有回归证据

| 审计面 | 当前控制 | 回归证据 |
| --- | --- | --- |
| Reader 大 token / BigInt | source、token、string、node、depth 在昂贵解析前有独立上限 | `yanshu-syntax::reader` limits tests；`reader_parser` fuzz |
| route 重叠检查 | Parser 最多接受 256 条 route，再执行重叠检查 | `rejects_route_sets_before_quadratic_overlap_work_can_grow_unbounded` |
| `let`、形参、pattern 遮蔽原语 | 类型、effect 与 review renderer 都先查词法作用域 | `yanshu-analysis` lexical/pattern/review shadowing tests |
| capability arity | capability 与普通 primitive 共用运行时 arity contract，静态分析同步检查 | runtime primitive table；analysis primitive inference tests |
| capability 返回值 | 返回值先检查操作契约，再走 portable value 包络并按规模消耗 fuel | `capability_results_must_obey_the_guest_value_envelope` |
| HTTP 敏感/framing header | 请求敏感头不进入 guest；guest 响应不能控制 framing、连接、认证或 cookie | `bearer_authentication_request_ids_and_sensitive_header_filtering_are_host_owned` |
| HTTP body/target/header 规模 | 请求 target、header 数量/字节、body、响应均有显式上限 | `protocol_boundary_rejects_media_type_json_and_oversized_bodies` |

| VersionStore 状态/事件崩溃一致性 | 有界 operation journal、幂等重放、整份事件日志原子替换 | register/promote/rollback durable-step injection tests |
| VersionStore 事件完整性 | v2 sequence + previousHash + canonical eventHash；旧日志由首个 v2 事件锚定 | event chain tamper tests；backup semantic verification |

## 本轮新增闭环

1. Bundle manifest 限 1 MiB，每个 Bundle 模块限 4 MiB；只接受常规文件，并通过 `take(max + 1)` 防止检查后增长导致无界读取。
2. Package source/manifest/lock 提供与文件加载器同限的 byte parser；文件读取同样改为受限流式读取。
3. HTTP/1 TCP 层显式配置 request-header deadline，不再依赖 Hyper 没有 timer 时会失效的默认值；真实慢 header 连接有回归测试。
4. `boundary_inputs` fuzz target 复用生产 Bundle/package byte parser 与 HTTP post-parser normalization，不复制一套“测试专用解析器”。
5. `yanshu-http` 按 auth、config、loader、observation、router、dispatch、transport、request、response 与 shadow 拆分；`lib.rs` 只保留公共 API，生成 `.yan` 语义未变化。
6. bytecode `programHash` 只哈希语义 inspection，不包含 span；artifact `contentHash` 则有意标识包含调试 span 的完整 canonical artifact。两者承担不同身份，不能互换。
7. VersionStore 在跨进程锁内先持久化有界 journal，再提交状态和整份事件日志；任何阶段失败都由下一次访问幂等完成。完整协议与平台限制见 [version-store-recovery.md](../engineering/version-store-recovery.md)。

## 仍不宣称解决

- libFuzzer 的 corpus 仍需长期积累、最小化和去敏治理；当前 PR/定时 smoke 只能发现被探索到的路径。
- HTTP 原始 wire parser 来自 Hyper，不由 Yanshu 复制实现；Yanshu fuzz 自己的 post-parser trust boundary，并用真实 TCP 测试 header deadline。
- 同 runner 双构建不等于 hermetic 或独立重构建。
- VersionStore 的 SHA-256 链没有密钥，只证明内部完整性而不证明事件作者或相对外部 checkpoint 的完整历史；合法前缀的尾部截断需要外部锚点才能识别，签名、透明日志和生产审批身份仍未完成。Windows safe std 也无法提供 Unix 同等的目录 `fsync`，因此不宣称覆盖所有断电/控制器故障。
- safe Rust 约束不证明第三方 crate 内部没有 `unsafe` 或漏洞。
- 进程内 fuel/结构上限不等于操作系统级内存、CPU 与墙钟隔离。

这些剩余项不能通过放宽 guest 边界来“解决”；需要 corpus 运营、独立 rebuilder、进程隔离和外部审计。
