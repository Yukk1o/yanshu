# Yanshu v0.13：版本化确定性标准库

状态：进行中。当前交付 `text@2`、`math@1`、`digest@1`、`json@1`、`decimal@1`、`list@1` 与 `map@1`；并发、网络、文件系统、通用 FFI 与 guest 依赖加载不在本阶段范围。

v0.13 不提升 `.yan` language version，当前最高仍为 v4。Library 版本本身就是显式门禁：`(libraries (text 1))` 保持原语义，只有声明 `(libraries (text 2))` 的程序能看到新增文本操作；数学、摘要、JSON、精确小数、列表与 Map 结构操作必须分别声明 `(libraries (math 1) (digest 1) (json 1) (decimal 1) (list 1) (map 1))`。

## 1. 兼容性

`text@2` 是 `text@1` 的超集。以下操作的参数、结果、Unicode scalar 语义与 fuel 模型不变：

- `length`
- `starts-with?`
- `ends-with?`
- `contains?`
- `replace`

可信注册表同时提供 v1 与 v2 backend。backend descriptor 的 operation 集合仍必须与对应 contract 精确相等；不能用 v2 backend 代替 v1，也不能向 v1 注入新增函数。

## 2. 新增操作

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `trim` | `fn(String) -> String` | 删除两端 Unicode White_Space |
| `lowercase` | `fn(String) -> String` | 与 locale 无关的 Unicode 小写映射 |
| `uppercase` | `fn(String) -> String` | 与 locale 无关的 Unicode 大写映射 |
| `split` | `fn(String, String) -> List<String>` | 按非空字面分隔符拆分，保留空字段 |
| `join` | `fn(List<String>, String) -> String` | 在相邻元素之间插入分隔符 |
| `substring` | `fn(String, Int, Int) -> String` | Unicode scalar 下标的半开区间 `[start, end)` |

大小写映射允许一对多，因此输出 scalar 数量不必等于输入。参考 safe Rust backend 与 conformance fixture 固定当前契约结果；其它 backend 必须逐项匹配，Unicode 表变化属于需要新 Library 版本的语义变化。

`split` 的空分隔符返回 `RUNTIME_LIBRARY_ARGUMENT`。`substring` 要求 `0 <= start <= end <= input scalar count`；负数、无法表示的巨大索引、逆序或越界都返回同一稳定机器码，不回显输入文本。

## 3. `math@1`

`math@1` 提供不扩大输入整数位数的确定性纯函数：

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `abs` | `fn(Int) -> Int` | 返回非负绝对值 |
| `sign` | `fn(Int) -> Int` | 负数、零、正数分别返回 `-1`、`0`、`1` |
| `min` | `fn(Int, Int) -> Int` | 返回较小值 |
| `max` | `fn(Int, Int) -> Int` | 返回较大值 |
| `clamp` | `fn(Int, Int, Int) -> Int` | 按 `value, minimum, maximum` 钳制到闭区间 |
| `gcd` | `fn(Int, Int) -> Int` | 返回非负最大公约数，`gcd(0, 0) = 0` |

`clamp` 要求 `minimum <= maximum`，否则在进入 backend 前返回 `RUNTIME_LIBRARY_ARGUMENT`。所有参数继续服从 portable Int 的 65,536 位上限，错误不回显整数内容。

v1 有意不包含 `pow` 与 `lcm`。这两类操作可能把两个合法输入放大成越界结果；在 Library 调用协议能表达“先扣 fuel，再做精确预检，最后才分配”以前，不用保守误拒绝规则污染稳定契约。

## 4. `digest@1`

`digest@1` 提供编码明确、输出有界的文本摘要：

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `sha256-text` | `fn(String) -> String` | 对字符串的 UTF-8 字节计算 SHA-256，返回 64 位小写十六进制文本 |
| `sha512-text` | `fn(String) -> String` | 对字符串的 UTF-8 字节计算 SHA-512，返回 128 位小写十六进制文本 |

名称中的 `-text` 是稳定语义的一部分：输入始终先按 UTF-8 编码，未来引入真正的 `Bytes` 类型时不会把现有函数重新解释为任意字节摘要。该库不提供随机盐、密钥或状态，不进入 capability closure。

SHA-256/SHA-512 是摘要算法，不是密码哈希、MAC 或数字签名。调用者不能用它们替代 Argon2 一类密码派生，也不能据此证明消息来自可信发送者。

## 5. `json@1`

`json@1` 为 AI、HTTP adapter 和业务系统提供严格、可恢复、确定性的普通 JSON 边界：

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `parse` | `fn(String) -> Result<Any, Map>` | 解析 UTF-8 JSON 文本 |
| `stringify-canonical` | `fn(Any) -> Result<String, Map>` | 输出无无效空白、对象键排序的规范 JSON |

JSON `null`、boolean、integer、string、array 和 object 分别映射为 guest `Nil`、Bool、Int、String、List 和仅含 String key 的 Map。v1 只接受十进制整数；带小数点或指数的 number 返回 `JSON_NON_INTEGER_NUMBER`，不会偷偷引入 IEEE-754、精度损失或依赖宿主的舍入语义。`-0` 解析为 Int `0`。

Parser 按解码后的对象键判断重复，因此 `"a"` 与 `"\u0061"` 属于同一个键；重复键返回 `JSON_DUPLICATE_KEY`，不采用 first-wins 或 last-wins。字符串正确组合 UTF-16 surrogate pair，并拒绝孤立 surrogate、控制字符和非法 escape。

规范序列化具有以下稳定规则：

- object key 按 String 的确定性顺序排列；
- 不输出缩进或其它无效空白；
- Int 使用无前导零的十进制表示；
- quote、反斜杠和控制字符使用固定小写 escape，其它 Unicode scalar 直接输出；
- Symbol、Symbol key Map、Result 和用户 Variant 不属于普通 JSON，返回 `JSON_UNSUPPORTED_VALUE`，不猜测带标签编码。

数据错误返回 guest 可检查的 `Err(Map)`，至少包含稳定 `code`；解析位置使用 UTF-8 byte `offset`，边界错误还可包含 `maximum`。`JSON_SYNTAX`、`JSON_DUPLICATE_KEY`、`JSON_NON_INTEGER_NUMBER`、`JSON_INPUT_LIMIT`、`JSON_OUTPUT_LIMIT`、`JSON_STRING_LIMIT`、`JSON_NODE_LIMIT`、`JSON_DEPTH_LIMIT`、`JSON_INTEGER_LIMIT` 与 `JSON_UNSUPPORTED_VALUE` 是 v1 的机器契约。fuel 耗尽、Library backend 故障和 capability 越权仍 fail-loud，不能被伪装成 JSON 数据错误。

## 6. `decimal@1`

`decimal@1` 提供不依赖浮点数、locale 或宿主默认舍入的固定点边界。一个系数 `coefficient` 与非负 `scale` 表示精确值 `coefficient / 10^scale`：

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `parse-scaled` | `fn(String, Int) -> Result<Int, Map>` | 把十进制文本解析为指定 scale 的整数系数 |
| `format-scaled` | `fn(Int, Int) -> Result<String, Map>` | 把整数系数格式化为固定 scale 文本 |
| `rescale` | `fn(Int, Int, Int, String) -> Result<Int, Map>` | 用显式舍入模式把系数从一个 scale 转到另一个 |

`parse-scaled` 接受可选负号、整数部分和可选小数部分；不接受前后空白、`+`、指数、分隔符或整数部分前导零。小数位少于目标 scale 时补零；超出的位只有全部为零才可无损丢弃，否则返回 `DECIMAL_PRECISION_LOSS`。`-0` 规范为整数 `0`。

`format-scaled` 始终输出固定的小数位数：系数 `-5`、scale `2` 输出 `"-0.05"`，scale `0` 不输出小数点。它不是 locale formatter，不读取系统小数点、货币符号或千位分隔规则。

`rescale` 必须接收以下六种稳定模式之一：

| 模式 | 非整除时的行为 |
| --- | --- |
| `exact` | 返回 `DECIMAL_ROUNDING_REQUIRED` |
| `toward-zero` | 向零截断 |
| `floor` | 向负无穷 |
| `ceiling` | 向正无穷 |
| `half-up` | 最近值；恰好一半时远离零 |
| `half-even` | 最近值；恰好一半时选择偶数系数 |

未知模式返回 `DECIMAL_INVALID_ROUNDING_MODE`，不能回退到宿主默认值。scale 范围是 `0..=1024`；文本、结果或 scale 越界分别使用 `DECIMAL_INPUT_LIMIT`、`DECIMAL_OUTPUT_LIMIT`、`DECIMAL_INTEGER_LIMIT` 与 `DECIMAL_SCALE_LIMIT`。这些业务数据错误都返回 guest 可检查的 `Err(Map)`，至少包含稳定 `code`，且不回显输入。

## 7. `list@1`

`list@1` 补充内核高阶 `list-map`、`list-filter`、`list-fold` 与 `sum` 之外的不可变结构操作：

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `reverse` | `fn(List) -> List` | 返回元素逆序的新列表 |
| `append` | `fn(List, List) -> List` | 按顺序连接两个列表 |
| `contains?` | `fn(List, Any) -> Bool` | 使用 portable value 结构相等判断成员 |
| `get` | `fn(List, Int) -> Result<Any, Map>` | 返回指定零基下标的元素 |
| `take` | `fn(List, Int) -> Result<List, Map>` | 返回前 `count` 个元素 |
| `drop` | `fn(List, Int) -> Result<List, Map>` | 丢弃前 `count` 个元素并返回后缀 |
| `slice` | `fn(List, Int, Int) -> Result<List, Map>` | 返回半开区间 `[start, end)` |

所有操作都保留元素本身，不执行回调，也不读取宿主状态。`contains?` 的相等语义递归比较类型、标量、列表顺序、Map 键值、Result 标签与用户 Variant 的类型/构造器/字段。

`get` 要求 `0 <= index < length`；`take` 和 `drop` 要求 `0 <= count <= length`；`slice` 要求 `0 <= start <= end <= length`。负数、无法表示的巨大整数和越界分别返回带 `LIST_INDEX_OUT_OF_BOUNDS`、`LIST_COUNT_OUT_OF_BOUNDS` 或 `LIST_RANGE_OUT_OF_BOUNDS` 的 guest `Err(Map)`。错误只包含稳定 `code` 与当前 `length`，不回显巨大索引。

`reverse` 与 `append` 只会因系统资源边界 fail-loud。空结果规范为 Nil；在 JSON 边界仍编码为 `[]`。

## 8. `map@1`

`map@1` 补充内核 `map/get/get-or/has-key?/assoc` 之外的不可变结构操作：

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `size` | `fn(Map) -> Int` | 返回键值项数量 |
| `keys` | `fn(Map) -> List` | 返回确定性顺序的键 |
| `values` | `fn(Map) -> List` | 返回与 `keys` 对齐的值 |
| `entries` | `fn(Map) -> List` | 返回两元素 `[key, value]` 列表 |
| `contains-value?` | `fn(Map, Any) -> Bool` | 使用 portable value 结构相等判断值 |
| `remove` | `fn(Map, Any) -> Result<Map, Map>` | 幂等删除 String 或 Symbol 键 |
| `merge-disjoint` | `fn(Map, Map) -> Result<Map, Map>` | 仅合并没有重名键的 Map |
| `merge-left` | `fn(Map, Map) -> Map` | 重名时保留左值 |
| `merge-right` | `fn(Map, Map) -> Map` | 重名时保留右值 |

`keys`、`values` 与 `entries` 共用同一稳定顺序：所有 String 键先于 Symbol 键，同类键按 Unicode scalar 的 UTF-8 字节字典序排列。空投影规范为 Nil，在 JSON 边界仍编码为 `[]`。`entries` 的每项固定为两个元素，不借用宿主 tuple。

`remove` 接收 Any 是因为当前静态类型没有 String-or-Symbol 联合类型；运行时只接受这两种 Map 键。其他值返回 `MAP_INVALID_KEY`，缺失的合法键返回未改变 Map 的 `Ok`。错误不回显原始键。

冲突策略必须出现在函数名中。`merge-disjoint` 遇到重名键返回 `MAP_KEY_CONFLICT` 与 `conflicts` 数量，但不回显键；`merge-left` 和 `merge-right` 没有业务错误，直接返回 Map。三个操作都不修改输入。

## 9. 类型与分析

`LibraryType::StringList` 表达封闭的 `List<String>` 边界。参数验证在 backend 调用前拒绝含非字符串元素的列表，结果验证也拒绝 backend 返回的混合列表。

静态分析不再用 `text@1` 布尔开关和函数名分支推导 Library 类型。它从程序声明的精确 `trusted_contract` 读取 operation，并用同一映射处理直接调用与一等函数值，例如：

```lisp
(list-map text/lowercase values)
```

Library 操作仍为 pure，不进入 capability closure。Parser 与效果分析通过可信契约表识别全部 Library operation；新增契约不再要求复制一份函数名清单。guest 定义、schema 与数据构造器不能遮蔽任何已发布的 Library 命名空间。

## 10. 资源边界与 fuel

所有新增操作在生成结果前检查：

- 单个文本操作结果最多 1 MiB；
- split 的根列表加字符串节点最多 10,000；
- 所有长度乘法与加法使用 checked 或 saturating arithmetic；
- substring 只在验证过的 UTF-8 scalar 边界切片；
- math 参数在 backend 工作前复核 65,536 位 portable Int 上限；
- JSON 输入、规范输出和单个解码字符串各最多 1 MiB，解析结果最多 10,000 节点、64 层，Int 最多 65,536 位；
- JSON parse 在进入 backend 前按 UTF-8 输入字节扣费；canonical stringify 在进入 backend 前按结构遍历、文本与整数规模扣费；
- decimal scale 最多 1,024，输入与输出最多 20,002 bytes，系数最多 65,536 bits；放大前先按 BigInt magnitude 位数预检必然越界的结果；
- list 输入与输出继续服从 10,000 节点、64 层、1 MiB scalar bytes 和 65,536 位单整数的 portable value 包络；append 在分配前检查合并结果；
- map 输入与输出服从相同 portable value 包络；keys/values/entries/remove/merge 在克隆或构造结果前完成投影与合并规模预检；
- backend 不使用 `unsafe`。

contract fuel 的 block size 为 64：

- `trim`：`1 + ceil(input scalars / 64)`；
- 大小写：`1 + ceil((input scalars + output bytes) / 64)`；
- split：`1 + ceil((input scalars + separator scalars + output bytes + segments) / 64)`；
- join：`1 + ceil((item scalars + separator scalars + output bytes + item count) / 64)`；
- substring：`1 + ceil((input scalars + output bytes) / 64)`；
- math 线性操作：`1 +` 每个参数各自占用的 64 位 magnitude block 数；
- `gcd`：`1 + left blocks * right blocks`。
- 文本摘要：`1 + ceil(input UTF-8 bytes / 64)`；结果长度固定为 64 或 128 ASCII 字节。
- JSON parse：`1 + ceil(input UTF-8 bytes / 64)`；
- JSON canonical stringify：`1 + ceil(value traversal and text work / 64)`。
- decimal parse：`1 + ceil((input bytes + scale bits + valid scale padding) / 64)`；
- decimal format：`1 + ceil((integer bits + scale bits + valid scale output) / 64)`；
- decimal rescale：`1 + ceil((integer bits + scale metadata + 4 * valid scale delta + mode bytes) / 64)`。
- list：`1 + ceil((portable input traversal + selected output clone work) / 64)`；运行时仍另行按返回值规范化成本扣费。
- map：`1 + ceil((portable map traversal + selected output clone work) / 64)`；运行时仍另行按返回值规范化成本扣费。

运行时随后继续按 portable result 的节点与字符串块扣费。fuel 不足时不会进入 backend；结果放大在实际分配前失败关闭。

## 11. 一致性要求

Parser、类型/效果分析、解释器、编译 VM、hover、completion、conformance 与开发者 Wiki 必须同时认识精确的 `text@2`、`math@1`、`digest@1`、`json@1`、`decimal@1`、`list@1` 与 `map@1` 契约。v4 conformance 同时执行解释路径与 `run-compiled` 路径，并覆盖：

- Unicode trim/大小写；
- split 保留空字段与 join；
- Unicode scalar substring；
- Library operation 作为一等函数值；
- v1 不暴露 v2 operation；
- 空分隔符、非法范围、错误列表元素及输出放大拒绝。

`math@1` conformance 还必须覆盖负数的绝对值与符号、闭区间钳制、非负 GCD、非法区间诊断以及解释器/VM 等价。

`digest@1` conformance 必须使用公开 SHA 标准向量固定 UTF-8 输入、小写十六进制输出和解释器/VM 等价；fuel 测试按 UTF-8 字节而不是 Unicode scalar 计量。

`json@1` conformance 必须固定整数-only 解析、Unicode escape、Nil 映射、规范对象键排序、无空白输出、重复键的可恢复稳定错误以及解释器/VM 等价。资源测试还要证明低 fuel 在 backend 前失败，输入、输出、节点和深度限制不会变成宿主 DoS。

`decimal@1` conformance 必须固定正负数精确解析、固定 scale 输出、六种显式舍入的负数与 tie 行为、可恢复精度错误以及解释器/VM 等价。资源测试还要证明大 scale 在 backend 前消耗对应 fuel，放大结果在 `BigInt` 分配前有界。

`list@1` conformance 必须覆盖顺序保持的 reverse/append、结构成员判断、get/take/drop/slice 的成功结果和稳定越界错误，以及解释器/VM 等价。资源测试还要证明遍历规模影响 fuel，合并结果在复制前受 portable envelope 限制。

`map@1` conformance 必须固定 String/Symbol 键顺序、keys/values/entries 对齐、结构值判断、幂等删除、三种显式合并策略、稳定冲突错误以及解释器/VM 等价。资源测试还要证明 entries 与 merge 的输出放大在实际分配前受 portable envelope 限制。

新增标准库不能借机读取环境、locale、时间、随机数、文件、网络或宿主 provider，也不能绕过显式 capability。
