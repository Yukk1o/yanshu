# Yanshu v0.13：版本化确定性标准库

状态：进行中。本阶段交付 `text@2`；并发、网络、文件系统、通用 FFI 与 guest 依赖加载不在本阶段范围。

v0.13 不提升 `.yan` language version，当前最高仍为 v4。Library 版本本身就是显式门禁：`(libraries (text 1))` 保持原语义，只有声明 `(libraries (text 2))` 的程序能看到新增操作。

## 1. 兼容性

`text@2` 是 `text@1` 的超集。以下操作的参数、结果、Unicode scalar 语义与 fuel 模型不变：

- `length`
- `starts-with?`
- `ends-with?`
- `contains?`
- `replace`

可信注册表同时提供 v1 与 v2 backend。backend descriptor 的 operation 集合仍必须与对应 contract 精确相等；不能用 v2 backend 代替 v1，也不能向 v1 注入新增函数。

## 2. 新增操作

| 操作 | 类型 | 语义 |
| --- | --- | --- |
| `trim` | `fn(String) -> String` | 删除两端 Unicode White_Space |
| `lowercase` | `fn(String) -> String` | 与 locale 无关的 Unicode 小写映射 |
| `uppercase` | `fn(String) -> String` | 与 locale 无关的 Unicode 大写映射 |
| `split` | `fn(String, String) -> List<String>` | 按非空字面分隔符拆分，保留空字段 |
| `join` | `fn(List<String>, String) -> String` | 在相邻元素之间插入分隔符 |
| `substring` | `fn(String, Int, Int) -> String` | Unicode scalar 下标的半开区间 `[start, end)` |

大小写映射允许一对多，因此输出 scalar 数量不必等于输入。参考 safe Rust backend 与 conformance fixture 固定当前契约结果；其它 backend 必须逐项匹配，Unicode 表变化属于需要新 Library 版本的语义变化。

`split` 的空分隔符返回 `RUNTIME_LIBRARY_ARGUMENT`。`substring` 要求 `0 <= start <= end <= input scalar count`；负数、无法表示的巨大索引、逆序或越界都返回同一稳定机器码，不回显输入文本。

## 3. 类型与分析

`LibraryType::StringList` 表达封闭的 `List<String>` 边界。参数验证在 backend 调用前拒绝含非字符串元素的列表，结果验证也拒绝 backend 返回的混合列表。

静态分析不再用 `text@1` 布尔开关和函数名分支推导 Library 类型。它从程序声明的精确 `trusted_contract` 读取 operation，并用同一映射处理直接调用与一等函数值，例如：

```lisp
(list-map text/lowercase values)
```

Library 操作仍为 pure，不进入 capability closure。Parser 保留所有可信 `text/...` 名称，guest 定义不能遮蔽 Library 命名空间。

## 4. 资源边界与 fuel

所有新增操作在生成结果前检查：

- 单个文本操作结果最多 1 MiB；
- split 的根列表加字符串节点最多 10,000；
- 所有长度乘法与加法使用 checked 或 saturating arithmetic；
- substring 只在验证过的 UTF-8 scalar 边界切片；
- backend 不使用 `unsafe`。

contract fuel 的 block size 为 64：

- `trim`：`1 + ceil(input scalars / 64)`；
- 大小写：`1 + ceil((input scalars + output bytes) / 64)`；
- split：`1 + ceil((input scalars + separator scalars + output bytes + segments) / 64)`；
- join：`1 + ceil((item scalars + separator scalars + output bytes + item count) / 64)`；
- substring：`1 + ceil((input scalars + output bytes) / 64)`。

运行时随后继续按 portable result 的节点与字符串块扣费。fuel 不足时不会进入 backend；结果放大在实际分配前失败关闭。

## 5. 一致性要求

Parser、类型/效果分析、解释器、编译 VM、hover、completion、conformance 与开发者 Wiki 必须同时认识 `text@2`。v4 conformance 同时执行解释路径与 `run-compiled` 路径，并覆盖：

- Unicode trim/大小写；
- split 保留空字段与 join；
- Unicode scalar substring；
- Library operation 作为一等函数值；
- v1 不暴露 v2 operation；
- 空分隔符、非法范围、错误列表元素及输出放大拒绝。

新增标准库不能借机读取环境、locale、时间、随机数、文件、网络或宿主 provider，也不能绕过显式 capability。
